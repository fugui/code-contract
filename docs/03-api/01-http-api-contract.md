## 1. 全局路由、鉴权守卫、安全基线与通用响应契约

### 1.1 路由前缀与双模接入规范
- **独立运行路径**：`/api/<endpoint>`（前端开发 `:5181` 代理或单二进制 `:8091` 直连）。
- **门户嵌入路径**：`/contract/api/<endpoint>`（由 `commonServer.Run(Options{ Prefix: "contract" })` 自动剥离 `/contract` 前缀，参见 [`01-system-architecture.md` §1.1](../02-design/01-system-architecture.md)）。
- **认证凭证传输**：所有受保护接口（含 `/api/events` SSE 实时流）统一通过 HTTP Header `Authorization: Bearer <JWT_TOKEN>` 传递凭证；**严禁在 URL Query 参数中传递 Token 或敏感凭据**。

### 1.2 RBAC 与公私域资源守卫标识符定义

| 守卫标识 | 中间件与数据层校验逻辑 | 拦截响应状态码 |
| :--- | :--- | :---: |
| `Public` | 免密开放路由（健康检查、登录配置与账密认证） | - |
| `JWT` | `commonAuth.AuthMiddleware`（強制校验 `HS256` 签名与 `exp` 声明，拒绝 `none` 算法） | 未携带或无效返 `401` |
| `AdminOnly` | `JWT` + `commonAuth.RequireAdmin("contract_admin")`（仅 `contract_admin` 或 `super_admin` 可访问） | 普通用户返 `403` |
| `ScopeReadGuard` | `JWT` + 公私域可见性过滤：`SHARED` 资源全员可读；`PRIVATE` 资源（Agent / 进程 / 快照 / 放置 / 依赖边 / 录制素材 / 仅 `PRIVATE` 来源的 `PROVISIONAL` `ArchProcess` 与未认领服务身份）仅 `owner_id == currentUser.ID` 本人及 `contract_admin` 可读 | 普通用户横向越权访问他人 `PRIVATE` 资源返 `403` |
| `ScopeWriteGuard` | `JWT` + 公私域写权限核验：`SHARED` 资源仅 `contract_admin` 可写；`PRIVATE` 资源仅 `owner_id == currentUser.ID` 本人可修改/启停/租用（管理员可删除违规私有资源或强制释放异常租约，但不得代持他人私有 Agent 发起录制/重放） | 越权修改或租用返 `403` |
| **`ScopeEnrollGuard`** | `JWT` + `ScopeReadGuard`（Agent 对本人可见）+ `discovery.v2_enabled == true` 开关校验（关闭返 `404`）+ `SHARED` 环境单次批量进程上限校验（`discovery.enroll_batch_limit_shared`，默认 `50`，超限返 `422 ENROLL_BATCH_LIMIT`）+ 每用户每 Agent 速率限制；禁止修改既有挂载的 `probe_desired_state` 与覆盖项 | 无权返 `403`；开关关闭返 `404`；超批量返 `422`；超频返 `429` |
| **`ModuleOwnerOrAdminGuard`** | `JWT` + 核验调用方为 `contract_admin` **或** 目标 `Module.owner_id == currentUser.ID` **或** 目标所属 `Subsystem.owner_id == currentUser.ID`（用于 L2 服务单宿主认领/取消认领与已认领服务 `.pb` 建议确认） | 非负责人且非管理员返 `403` |
| `CIOrAdminGuard` | 支持 `AdminOnly`（管理员 `Authorization: Bearer <JWT>`）**或** 专用请求头 `X-Contract-CI-Token: <TOKEN>`（服务端计算 SHA-256 并与 `contract_settings.ci_gate_token_sha256` 执行 `subtle.ConstantTimeCompare` 常量时间比对，严禁 URL Query 传参、源码硬编码或日志打印明文，独立挂载滑动窗口速率限制） | 缺失/错误返 `401`；普通用户 JWT 返 `403`；超频返 `429` |
| `GitWebhookGuard` | 优先按路径 `:repoId` 精准定位 `GitRepo`（兼容按归一化 `ssh/https` 仓库 URL 匹配，仅限唯一命中），从 Header 读取 `X-Gitlab-Token`（GitLab）、`X-Hub-Signature-256`（GitHub SHA-256 HMAC）或 `X-Gitea-Signature`（Gitea），通过 `CONTRACT_CRYPTO_KEY` AES-256-GCM 解密 `GitRepo.WebhookSecretEncrypted` 后执行 `subtle.ConstantTimeCompare` / `hmac.Equal` 常量时间比对；强制挂载滑动窗口速率限制与 `commonAudit.Skip` | 未匹配唯一仓库返 `404`；密钥缺失或验签不通过返 `401`/`403`；超频返 `429` |

> **详细角色权限与审计快照策略**：参见 [`04-control-plane-and-web-console.md` §5.1 & §5.2](../02-design/04-control-plane-and-web-console.md) 及 [`05-database-schema.md` §5](../02-design/05-database-schema.md)。

### 1.3 标准分页、64 位整数编码与错误响应信封

1. **通用分页 Query 参数**：`page`（默认 `1`，`>=1`）、`page_size`（固定允许 `15 / 25 / 50 / 100`，默认 `25`）。
2. **标准分页响应 (`200 OK`)**：
   ```json
   {
     "items": [],
     "total": 42,
     "page": 1,
     "page_size": 25
   }
   ```
3. **无符号 64 位整数精度防腐**：所有 `ullSNO` (`sno`)、`ullStatusCode` (`status_code`) 及大整数 ID 在 JSON 响应中按 [`05-database-schema.md` §1.4](../02-design/05-database-schema.md) 序列化为十进制字符串（或标准 JSON Number），前端 TypeScript 严格禁止使用 `any`。
4. **标准错误、`409` 排他租约冲突与 `A-09` 实现进程互斥冲突响应**：
   - 常规错误（`400 / 401 / 403 / 404 / 409 / 500 / 503`）：`{"error": "具体的中文错误原因说明", "code": "ERROR_CODE"}`
   - Agent 排他租约争用冲突（`409 Conflict`，参见 [`01-system-architecture.md` §3.2](../02-design/01-system-architecture.md)）：
     ```json
     {
       "error": "目标 Agent [192.168.56.19:9091] 正被用户 [张三] 的录制任务占用",
       "code": "AGENT_LEASE_CONFLICT",
       "conflict_agent_id": 2,
       "lease_type": "RECORDING",
       "lease_ref_id": 108,
       "lease_holder_id": 15,
       "lease_holder_name": "张三",
       "lease_acquired_at": "2026-10-29T10:00:00Z",
       "lease_expires_at": "2026-10-29T10:32:00Z"
     }
     ```
   - 多实现契约同进程互斥冲突（`409 Conflict`，`A-09 / F-02.1`，参见 [`ADR-16`](../05-adr/16-multi-implementation-service-contract-adr.md) §3.4）：
     ```json
     {
       "error": "多实现契约 [pkg.IfaceSvc] 的实现模块不能部署在同一架构进程 [sut-biz-b] 中（已存在实现 impl_key='b' / 模块 MOD_B）",
       "code": "CONTRACT_IMPL_PROCESS_CONFLICT",
       "conflict_contract_id": 12,
       "conflict_contract_name": "pkg.IfaceSvc",
       "conflict_impl_key": "b",
       "conflict_module_id": 102,
       "conflict_module_code": "MOD_B",
       "arch_process_id": 7,
       "arch_process_code": "sut-biz-b"
     }
     ```
   - **CSG 仿真测试控制面互斥与 Mesh 传输边界响应（`F-34`, [`ADR-21`](../05-adr/21-csg-aware-agent-service-discovery-and-replay-mock-adr.md)）**：
     - **`409 Conflict (CSG_SERVICE_ALREADY_PUBLISHED)`**：在 `PUB_STUB` 模式下，前置 `csgdlink.Sub(svcName)` 检测到真实 CSG 注册中心中该下游服务当前已有在线实例（`len(instances) > 0`），拒绝向真实 CSG 注册同名桩以免违反 `NO_DUPLICATED_SERVICE` 或污染同租户其他调用方：
       ```json
       {
         "error": "目标下游服务 [HelloService-HelloService] 在 CSG [10.29.92.80:31806] 上已有 1 个真实实例在线，禁止启用 PUB_STUB，请切换为 MOCK_SERVER 全隔离沙箱模式",
         "code": "CSG_SERVICE_ALREADY_PUBLISHED",
         "service_name": "HelloService-HelloService",
         "csg_addr": "10.29.92.80:31806",
         "online_instances": ["tcp://ipv4:10.29.92.80:18500"]
       }
       ```
     - **`422 Unprocessable Entity (CSG_DATAPLANE_MESH_UNSUPPORTED)`**：依据 [`ADR-22` v2.0.0](../05-adr/22-pluggable-transport-driver-and-mesh-capture-adr.md)，`MOCK_SERVER` 与 `PUB_STUB` 模式下已支持将 `dophi_mesh://` 自动改写/发布为 `tcp://` 并在发送副本中自动将 `ucProtocol (4 -> 1)` 归一化（不再报 `422`）；本状态码仅在 **`CLIENT_INJECT`** 模式下，当现网目标被测服务仅发布了 `dophi_mesh://` 实例且无可用 TCP 监听端口可供直拨注入时返回，引导用户切换 `MOCK_SERVER` 模式：
       ```json
       {
         "error": "目标服务 [MeshOnlySvc] 当前在 CSG 中仅发布了 dophi_mesh:// 实例且无可用 TCP 监听端口，CLIENT_INJECT 无法直拨注入，请切换 MOCK_SERVER 仿真模式",
         "code": "CSG_DATAPLANE_MESH_UNSUPPORTED",
         "service_name": "MeshOnlySvc",
         "pid": 42190,
         "observed_transports": ["dophi_mesh"]
       }
       ```
   - **以现网发现为中心的纳管、认领与迁移冲突响应（`F-36`~`F-39`, [`ADR-24`](../05-adr/24-csg-discovery-process-centric-and-physical-logical-boundary-adr.md) §6）**：
     - **`422 IDENTITY_AMBIGUOUS`**：`Enroll` 或 `quick-record` 过程中目标进程命中 `>= 2` 个 `ArchProcess` 候选且请求未提供 `identity_overrides`，拒绝自动猜绑并返回 `candidates: []ArchProcessCandidate`；
     - **`422 LOW_CONFIDENCE_CONFIRM_REQUIRED`**：目标进程 `cmdline` 不可读仅由 P3 `procName` 兜底命中且 `confirm_low_confidence != true`，要求前端二次确认；
     - **`422 ENROLL_BATCH_LIMIT`**：`SHARED` 环境单次 `Enroll` 请求所选进程数超过 `discovery.enroll_batch_limit_shared`（默认 `50`）；
     - **`422 CLAIM_PLACEMENT_MISMATCH`**：L2 认领进 `Module M` 时违反不变量 I4（权威环境 `ACTIVE` 放置不属同一 `ArchProcess P` 或 `M.arch_process_id != P`）；
     - **`409 DEPENDENCY_REFERENCED`**：`Unclaim` 或删除 `Module` 前违反不变量 I6（服务被 `contract_module_dependencies.service_id` 引用，响应附带 `referencing_modules`）；
     - **`409 LEASE_CONFLICT`**：`quick-record` 等抢占 Agent 排他租约失败（语义与 `AGENT_LEASE_CONFLICT` 同源，附带当前持锁人与到期时间）。

## 2. 控制面 REST / SSE 接口契约字典 (`code-contract-server` 对外 `/api/*`)

### 2.1 基础探针、认证会话与平台治理域 (`SC-01`, `F-16`)

| 方法 | 路由路径 | 守卫要求 | Query / Body 核心参数 | 响应 JSON 结构与状态码 | `AuditAction` (`module:action`) |
| :---: | :--- | :---: | :--- | :--- | :--- |
| `GET` | `/api/health` | `Public` | 无 | `200`: `{"status":"healthy","service":"Code-Contract","module_key":"contract","version":"...","timestamp":"..."}` | - |
| `GET` | `/api/auth/config` | `Public` | 无 | `200`: `{"oauth2_enabled":bool,"password_login_enabled":bool,"dept_api_url":string}` | - |
| `POST` | `/api/login` | `Public` | Body: `{username, email?, password}` | `200`: `{"token":string,"user":{id,username,name,roles}}`<br>`400`: 参数缺失；`401`: 账密错误；`403`: 账号禁用或本地登录关闭 | `auth:login` |
| `GET` | `/api/oauth2/authorize` | `Public` | 无 | `302`: 跳转 SSO 授权页；`404`: OAuth2 未启用 | - |
| `GET` | `/api/oauth2/callback` | `Public` | Query: `code, state` | `302`: 签发 JWT 并重定向前端 | - |
| `GET` | `/api/me` | `JWT` | 无 | `200`: `{id, username, name, employee_id, department_id, department_name, roles, is_super_admin, is_module_admin, required_ad_role: "contract_admin"}`<br>`401`: 未认证 | - |

#### 2.2.1 拓扑布局 JSON 载荷 Schema 与校验规则 (`F-04.3`, [`ADR-15`](../05-adr/15-scalable-topology-focus-and-layout-persistence-adr.md) §6)

| 类型 | 字段定义 | 校验规则 |
| :--- | :--- | :--- |
| `SavedNodePosition` | `{x: number, y: number, pinned?: boolean}` | `x / y` 必须为有限实数（拦截 `NaN / ±Inf`）；单层平铺下为当前聚焦层平面坐标（含内部子节点 ID 及外部传送门复合键 `${focusScope}::${extNodeId}`） |
| `node_positions` | `Record<nodeId, SavedNodePosition>` | 条目数 `<= 5000`；键非空且长度 `<= 128`（含 `::` 复合键） |
| `SavedExpandState` | `{level: int, overrides?: Record<nodeId, boolean>}` | 向后兼容保留：`level ∈ [0, 16]`，`overrides <= 5000`（`ADR-17` 单层下钻模式仅需保持反序列化兼容） |
| `SavedFilterState` | `{subsystem_ids?: string[], only_my_scope?: boolean, status?: "ALL" \| "ABNORMAL" \| "VIOLATION_ONLY", ego_node_id?: string, ego_hops?: 1 \| 2, hide_isolated?: boolean, hub_fold?: boolean}` | `subsystem_ids` 条目数 `<= 100`；枚举值严格白名单 |
| `SavedViewport` | `{x: number, y: number, zoom: number}` | 有限实数；`zoom ∈ [0.15, 2.0]` |
| `focus_scope` | `string` | 缺省规范化为 `"GLOBAL"`；必须匹配 `^(GLOBAL\|(sub\|grp\|pgrp\|proc)_[0-9]+\|ext_container\|undeployed_container)$`；`SHARED` 记录恒为 `"GLOBAL"` |
| `TopologyLayoutSummary` | `{id, scope, view, name, description, focus_scope, is_default, structure_version, revision, updated_at}` | 列表接口使用，不含任何大 JSON 载荷 |
| `TopologyLayoutDetail` | `TopologyLayoutSummary` + `{schema_version, node_positions, expand_state, filter_state, viewport, created_by, updated_by, created_at}` | 详情接口使用 |

- **请求体上限**：全部布局写接口经 `http.MaxBytesReader(1MB)`，超限返回 `413 {"error": "...", "code": "PAYLOAD_TOO_LARGE"}`；
- **防批量赋值**：Handler 仅绑定专用请求 DTO，`scope`、`owner_id`、`revision`、`created_by`、`updated_by` 一律由服务端决定；
- **审计**：全部写操作接入 `commonAudit`，仅记录摘要（`view`、`focus_scope`、`name`、坐标条目数、`structure_version`、`revision`），**不得**将 `node_positions` 等大 JSON 写入字段级 Diff；
- **前端降级**：深链 `topo_layout_id` 收到 `403 / 404` 时降级至团队基准并提示，不视为错误中断。

### 2.7 SSE 实时事件流接口 (`GET /api/events`)

- **路径与鉴权**：`GET /api/events`，挂载 `commonAuth.AuthMiddleware`（前端通过 `fetch` + `ReadableStream` 在 `Authorization: Bearer <JWT>` Header 中传递令牌，严禁 URL Query 传参）。
- **过滤参数**：Query `session_id?`（订阅指定录制批次实时帧与状态）、`task_id?`（订阅指定重放任务进度）。若传入他人 `PRIVATE` `session_id`，立即返回 `403 Forbidden`。
- **事件帧类型 (`event: <type>\ndata: <json>\n\n`)**：
  1. `traffic.preview`：Track A 快轨实时流量预览摘要（`{session_id, process_id, direction, sno, service_name, operation, captured_at_ns}`）；
  2. `traffic.persisted`：Track B 慢轨往返配对落盘完成通知（`{session_id, record_id, sno, exchange_type, latency_us, status_code, decode_status}`）；
  3. `session.lifecycle`：录制批次状态流转、进程 PID 重启热更新（`PROCESS_RESTARTED`）、存量连接诊断或达到时长/帧数上限自动停录（`COMPLETED_BY_LIMIT`）；
  4. `agent.lease_changed`：Agent 在线状态或排他租约变更通知（`{agent_id, status, lease_type, lease_holder_name, lease_expires_at}`）；
  5. `replay.item_done`：单条重放请求执行与断言完成通知（`{task_id, item_id, record_id, result_status, latency_us}`）；
  6. `replay.completed`：重放任务整包完成汇总（`{task_id, lifecycle_state, result_status, total_requests, passed_requests, mock_hit_count, mock_miss_count}`）；
  7. `agent.probes_updated`：Agent 预挂探针就绪快照更新通知（`{agent_id, armed_digest, diagnostics: []ProcessDiagStatus}`，仅向对该 Agent 具备 `ScopeReadGuard` 可见性的订阅客户端广播）；
  8. `git_sync.completed`：Git 仓库手动/Merge 自动同步与 Bundle 编译完成广播（`{git_repo_id, bundle_id?, commit_sha, status, compiled_schema_id?, changed_files_count, error_message?}`，已认证订阅者可接收）；
  9. `mr_gate.updated`：Git MR 四合一静态门禁预检状态变更与豁免广播（`{check_run_id, git_repo_id, bundle_id?, mr_iid, head_commit_sha, target_head_sha, status, compile_passed, lint_passed, duplicate_passed, breaking_passed}`，已认证订阅者可接收）；
  10. `notification.created`：持久化站内通知实时抵达推送（`SSEBroker` 客户端订阅结构体显式绑定 `userID`，严格调用 `BroadcastToUsers([]uint64{recipient_user_id}, ...)` 仅向目标 `recipient_user_id` 本人的订阅通道下发 `NotificationItemDTO` 及最新 `unread_count`，**绝不按全员广播**）；
  11. `attribution_job.updated`：阶段 2 异步回溯归因任务状态与进度广播（`{job_id, trigger_type, target_id, status, matched_count, unresolved_count, conflict_count, last_error?}`，向触发人及具观测权限订阅者推送，驱动契约目录与收件箱实时刷新）。
